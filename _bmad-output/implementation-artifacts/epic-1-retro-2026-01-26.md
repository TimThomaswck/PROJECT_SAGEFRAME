## 🔧 Challenges & Growth Areas

### 1. **Story 1-1: Broken pyside-cli Template (CRITICAL)**
**Challenge:** Official PySide6 template was fundamentally broken
- Missing core UI classes (Ui_MainWindow, Ui_UpdateWidget)
- Disabled resource loading
- Hardcoded version strings
- Missing dependencies

**Impact:** Required extensive patching and workarounds; delayed Story 1-1

**Root Cause:** Dependency on external tooling without pre-validation

**Resolution:** Team researched, ran proper build commands, replaced workarounds with generated UI files

### 2. **Database Security (CRITICAL - UNRESOLVED)**
**Issue:** Mood data stored in plaintext in `~/.sageframe/sageframe.db`

**Evidence:** Flagged in Story 1-3 code review

**Impact:** Security vulnerability for user data

**Status:** 🚨 **CARRIES FORWARD TO EPIC 2**

## 🎯 Key Lessons Learned

### Lesson 1: Validate External Dependencies Early
**Context:** pyside-cli template was broken
**Learning:** Don't assume external tools work as documented
**Action:** Add dependency validation to story preparation

### Lesson 2: Security Must Be Designed In, Not Added Later
**Context:** Database encryption flagged in code review
**Learning:** Security requirements must be in acceptance criteria from the start
**Action:** Add security checklist to story creation workflow

### Lesson 3: Performance Testing Should Be Proactive, Not Reactive
**Context:** NFR1/NFR2 tests missing in early stories
**Learning:** Performance requirements need explicit test coverage from day one
**Action:** Include performance test requirements in all story templates

### Lesson 4: Code Reviews Are Highly Effective
**Context:** Story 1-3 review found 12 issues, most auto-fixed
**Learning:** Formal reviews catch issues before they compound
**Action:** Continue code reviews for complex stories

### Lesson 5: MVVM Pattern Scales Well
**Context:** Consistent architecture across all 7 stories
**Learning:** Upfront architectural decisions pay dividends
**Action:** Maintain MVVM discipline in Epic 2
